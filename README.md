# ①課題名
読んだ内容を覚えるための読書メモ

## ②課題内容（どんな作品か）
- 読んだ本の「心に残ったところ」と「そこから考えたこと」を書きとめておく、読書メモのアプリです
- 三宅香帆さんの鑑賞ノートの形にならって、「ハイライト」「発見」「比較」「質問」の4つの欄に書きます
- 書いたメモは localStorage にしまわれ、ページを閉じても残ります。新しいメモが上に来るように、カードで並びます
- カードには本のタイトルと日付だけが出ていて、「開く」を押すと中身が見えます。中身を見る前に「何を書いたっけ」と一度思い出してみる、読んだ本を覚えておくための仕掛けです

## ⑤工夫した点・こだわった点
- タブを作りました。（AIによる作業）
- 書いた欄だけを、見出しつきでカードに出すようにしました（空の欄は出しません）
- 同じ本を続けて書くことが多いので、書きとめたあとも本のタイトルは残るようにしました
- 「全部消す」には確認の小窓（confirm）をつけて、うっかり消さないようにしました
- 日付は Date と曜日の配列で、カレンダーで選べて、最初は今日の日付が入っています
- ページの欄は、はじめは作りましたが、メモの中に直接書くほうが自然だと感じて、なくしました
- 字体は、画面で読みやすいゴシック体（Google Fonts の Zen Kaku Gothic New）にしました
- 自分で使ってみると、著者名・Kindle／紙の本（ラジオボタン）情報が必要だとわかり、追加しました。
- 「直す」ボタンで、書いたメモをあとから直せるようにしました。直すときは日付を元のままにして、新しいメモとして増えないようにしました
- 本のタイトルを押すと、その本のメモだけが並ぶようにしました。「言葉でさがす」の仕組みを、そのまま使い回しています
- 日めくりカレンダーのように、1日1つ、読書にまつわる言葉が出るようにしました。2026年1月1日から何日たったかを数え、言葉の数でわったあまりで、どの言葉にするかを決めています

- チャレンジ1：音声入力。「話す」を押して話すと、その欄に文字が入ります（Chrome の音声認識を使っています）。
- チャレンジ2：言葉でさがす。1文字打つたびに、その言葉が入っているメモだけが並びます

## ⑥難しかった点・次回トライしたいこと（又は機能）
### 難しかった点
- 「開く」ボタンは、ページを開いたときにはまだなく、書きとめたあとに作られます。そのため、ボタンに直接ではなく、最初からあるカード置き場（#list）に「この中のボタンが押されたら教えて」と頼む書き方が必要でした
- 画面の高さによって、「全部消す」が書く欄に重なってしまいました。CSSの min-height: 0 が原因で、書く欄の箱が中身より小さく縮んでいたことがわかりました
- ページの欄を消すときに、HTMLとJavaScriptの何か所も消す必要があり、1か所でも残っていると動かなくなることを知りました
- 「直す」を作ったとき、保存できていなかったため、上書きのつもりが新しいメモとして1枚増えていました。push（うしろに足す）と records[番号] = …（その場所に入れかえる）のちがいを知りました


### 次回トライしたいこと（メモがたまったときの見せ方）
- 本ごとにまとめて見せる
- カードが多くなったら「もっと見る」で少しずつ出す

### 次回トライしたいこと（読んだ本を覚えておくために）
- 書いた日から1日後・1週間後・1か月後に、そのメモを「今日ふりかえるメモ」として上に出す
- 過去のメモをランダムに1枚出す

### 次回トライしたいこと（画像を取り込む）
- 本のページのスクショを、メモにつけられるようにする。localStorage には入る量に限りがあるので、画像を小さく縮めてからしまう
